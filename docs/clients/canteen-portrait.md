# Android 食堂竖屏工作台设计

权威需求：[一期需求](../requirements-phase1.md)  
客户端总设计：[design.md](design.md)  
视觉参考：[docs/ui](../ui/README.md)（横屏参考图；竖屏**信息结构对齐**，不像素级照搬侧栏）

本文把「食堂 / 管理员 / 总管」在 **Android 竖屏**上的信息架构、路由、人体工程学与分阶段交付写死。实现以本文为准；与横屏 Web 共用同一 Axum API，不新增权限码。

---

## 0. 目标与非目标

### 目标

1. 食堂人员用手机竖屏完成日常运营：看人数、定本周选菜、维护菜谱、看强提醒/评分/评语。
2. **同一账号、同一会话**：登录与 Web / 员工 App 相同；壳按 `GET /api/me` 的 `roles` / `permissions` 显隐，不在本地发明权限。
3. 交互对齐产品偏好：概览优先、点进编辑、一屏一个主操作、状态行清晰；触控目标约 ≥48dp。

### 非目标（本批不做）

- 不做 Android **横屏**工作台（与总设计一致）。
- 不做独立「食堂 App」包：仍是同一个 `com.duolinzao.app`，登录后进不同壳。
- 总管专页（邮箱 / LLM / 签名 / 导出 / 审计 / 阈值 / 找回 / 建食堂）**可进「更多」但实现可后置**；食堂日常路径优先。
- 不接应用商店；分发仍走站点 `/app/` + 签名发布。

## 1. 登录后路由

1. 共用现有登录 / 注册页（Passkey 默认，失败回退密码等，见 [design.md](design.md) §3.2）。
2. `GET /api/me` 成功后：
   - 若持有**工作台能力**（见下）→ 进入 **食堂竖屏壳** `CanteenShell`。
   - 否则若仅有员工自助能力（`meal.self_read` / `meal.self_write` 等）→ 进入现有 **员工壳**。
   - 两者皆无 → 错误页「账号无可用功能」+ 退出。
3. **工作台能力**判定（任一即可）：
   - 角色含 `canteen` / `admin` / `super_admin`，**或**
   - 权限含食堂运营相关码：`menu.read` / `menu.write` / `optimizer.read` / `rating.admin_read` / `comment.admin_read` / `meal.admin_override` / `user.invite` / `system.super` 等（与 Web 侧栏 `show` 条件同思路）。
4. **双角色**（同时有员工自助 + 工作台）：
   - 默认进 **食堂壳**（运营人员更常先看人数/选菜）。
   - 食堂壳「我的」提供 **「切换到员工端」**；员工壳「我的」提供 **「切换到食堂工作台」**（仅当具备工作台能力时显示）。
   - 切换只改本地导航根，不重新登录。
5. 401 → 清会话回登录（与员工端相同）。

## 2. 信息架构（竖屏）

### 2.1 壳层

```
登录 / 注册（共用）
 └─ CanteenShell
      ├─ 顶栏：当前食堂名称（可切换） + 可选日期（人数页）
      ├─ 底部四 Tab
      │    ├─ 人数
      │    ├─ 选菜
      │    ├─ 菜谱
      │    └─ 更多
      └─（可选）员工壳 ←→ 切换入口在「我的/更多」
```

**为何四 Tab、选菜独立：** 一期里「一周排菜」是食堂最高频路径；放进「更多」会藏深。人数是开班第一眼；菜谱是库维护；评分/强提醒/评语/改单/邀请频率较低，收进「更多」分组列表（Apple Settings 式）。

### 2.2 顶栏 · 食堂范围

- 管理范围内仅 **1** 个食堂：顶栏显示名称，不可点（或点开只读说明）。
- **≥2** 个（含 `super_admin` 全局）：顶栏为选择器，切换后所有子页共用 `auth.canteenId`（对齐 Web `managedCanteens()`）。
- 无任何可管食堂：人数/选菜/菜谱空态「没有可管理的食堂」，引导联系超管（不自建，除非后续做超管建食堂页）。

### 2.3 Tab「人数」

- 主内容：所选日期下早/午/晚 **有效报餐人数**三张大卡（数字为主，约 48sp+）。
- 日期选择：默认上海时区「今天」；左右切日或日期选择器。
- 锁定状态一行：`该日三餐已锁定` / `尚未锁定`（一次锁定次日三餐，**不按餐次分锁**——与需求一致；勿做「午餐锁、晚餐未锁」）。
- 不展示分类占比等参考图里的装饰统计。

### 2.4 Tab「选菜」（选菜优化）

- **默认周视图**：周一～周日 × 早/午/晚格子；格内菜/饭/汤摘要分开，不混一行。
- 点格子 → **当餐选定页**：三类分节列表；卡片可有图/占位与口味标签；**勾选/取消立即保存**（`optimizer.read`）；主按钮「保存并下一餐」按需求顺序跳转。
- 色阶只表示暗线偏好高低（更高更绿、更低更红）；**不展示**偏好分、Elo、「预计评分」等（见 ui README「不要照搬」）。
- 无 `optimizer.read`：Tab 隐藏或进 Tab 后说明无权限。

### 2.5 Tab「菜谱」

- 顶部分段或页签：**菜 | 饭 | 汤**（强制分组）。
- 列表：名称、启用状态、可选缩略图；点行 → 编辑表单。
- 主操作：右上或 FAB「新建」（需 `menu.write`）。
- 表单：类型仅菜/饭/汤；口味标签；图片上传/更换/移除（非必填）；启用开关；**无备注字段**。
- 从强提醒「去停用」深链进入同一表单并聚焦启用开关（停用须在此确认，不自动下架）。

### 2.6 Tab「更多」（分组列表）

按权限显隐，推荐分组：

| 分组 | 项 | 权限/角色 |
|------|----|-----------|
| 反馈 | 强提醒 | `menu.write` / `optimizer.read` / `system.super`（对齐 Web） |
| 反馈 | 评分汇总 | `rating.admin_read` |
| 反馈 | 评语 | `comment.admin_read` |
| 管理 | 截止后改单 | `meal.admin_override` |
| 管理 | 邀请码 | `user.invite` |
| 账户 | 账户设置 | 人人有（复用员工账户能力） |
| 账户 | 设备与 Passkey / 新设备确认 | 本账号 |
| 账户 | 检查更新 | 同员工端 |
| 账户 | 切换到员工端 | 仅双角色 |
| 账户 | 退出登录 | 人人有 |
| 总管（后置） | 导出 / 审计 / 邮箱 / 阈值 / 找回 / LLM / 应用签名 / 建食堂 | 对应超管权限 |

第一版实现可只做「反馈 + 账户 + 改单/邀请」；总管组标 `@wip` / 后续迭代。

**强提醒页：** 列表展示均分低的菜；操作是「去菜谱确认停用」，不在列表上直接下架。

**评分汇总 / 评语：** 按菜/饭/汤筛选或分组；匿名评语不展示账号。

**邀请码：** 选角色（员工/食堂）、食堂范围、次数；创建后码**只展示一次**（对齐 Web）。

## 3. 人体工程学

1. **拇指区：** 主操作（新建、保存并下一餐、切换报餐类操作）靠下或 FAB；破坏性操作（停用、吊销）需确认。
2. **一屏一主操作：** 编辑页底部一条主按钮；次要操作用文字按钮。
3. **状态先行：** 人数页锁定态、菜谱启用态、强提醒「待处理」用状态行/胶囊，不只靠颜色。
4. **空态与错误：** 短句说明下一步（绑食堂、要权限、网络失败可重试）；成功提示用绿字（延续 #20），不用红字表示成功。
5. **Passkey：** 登录页与员工端相同；食堂账号无 GMS 时同样回退密码，密码入口不要藏过深（可在食堂场景默认展开密码区——实现时二选一，默认与员工一致并在文案标明「无凭据时可点密码登录」）。
6. **横屏 Web：** 本设计替代「手机上挤横屏侧栏」；不要求食堂人员用手机开 Web 工作台。

## 4. API 与 mock

- 全部走现有 `/api/canteens/...`、`/api/admin/...`、`/api/me...`；写请求带 `X-DLZ-Requested: 1`。
- `useMock=true` 时扩展 `MockRepository`：人数、菜谱分组、选菜周数据、强提醒样例，便于无后端演示与仪器化冒烟。
- 不新增后端权限模型。

## 5. 分阶段交付

| 阶段 | 内容 | 出口 |
|------|------|------|
| C0 | 本文设计合入 | 评审通过 |
| C0+ | Web 窄屏同壳：`useNarrow(900)` + `CanteenPortraitShell`，复用横屏页组件 | 食堂窄屏竖屏四 Tab；宽屏侧栏不动 |
| C1 | 路由 + `CanteenShell` 四 Tab 骨架；人数页；更多→账户/设备/更新/切换员工/退出 | 食堂账号登录进工作台；双角色可切换 |
| C2 | 菜谱列表（菜/饭/汤）+ 新建/编辑（含图） | 与 Web 菜谱读写对齐 |
| C3 | 选菜周视图 + 当餐选定（立即保存、下一餐） | 食堂主路径可竖屏跑通 |
| C4 | 更多：强提醒、评分汇总、评语 | 反馈闭环 |
| C5 | 改单、邀请码；总管组按需 | 管理能力对齐 Web 子集 |

仪器化测试：C1 起对「食堂账号 → 见人数 Tab」加 mock 冒烟；不挡主 `ci.yml`，仍放 `android.yml`。

## 5.5 Web 窄屏同壳（与本设计同 IA）

- 路由同样按 `GET /api/me` 的角色/权限判定工作台能力（角色 `canteen` / `admin` / `super_admin` 任一，或运营/总管权限码；与 Web 侧栏 `show` 条件同思路）。
- 判定只看 viewport（`matchMedia('(max-width: 900px)')`，不断点 UA）：窄屏进竖屏壳，宽屏进现有侧栏。断点 900px 与 `OverviewPage` 卡片堆叠断点一致。
- 双角色默认食堂壳，「更多」↔员工端互切只改本地导航，不重登。
- 视觉稿：`docs/ui/canteen-portrait-mock/`（四屏：人数/选菜/菜谱/更多）。
